# 流程：扫码录入物品

> 涉及模块：`inventory`、`locations`（可选）、`documents`（可选） ｜ 触发：用户扫商品条码 ｜ 权限：`inventory.read`、`inventory.write`、`inventory.stock.adjust`、`inventory.catalog.lookup`（可选）

## 1. 目标

用商品条码把「买回来 → 建物品 → 入库」压缩成几步：已知条码直接补货，未知条码先建物品，资料可以稍后补；支持连续扫多件，不要求联网查商品库。

## 2. 参与方与数据所有权

| 数据 | 拥有者 |
|---|---|
| 相机/扫码枪解码、扫描会话 | 卫星或浏览器（本地） |
| 条码↔物品映射、物品、批次、库存流水 | `inventory` |
| 外部商品库查询缓存 | `inventory` |
| 位置 | `locations` |
| 物品照片/说明书 | `documents` |

## 3. 步骤

1. 用户打开扫码页；相机、蓝牙/USB 扫码枪（键盘输入）或手动输入均可，解码在客户端完成，不上传相机帧。
2. 客户端把码交给 `inventory.barcodes.resolve`，可一次提交多个；服务端做 GTIN 校验与归一化，只查本地映射。
3. 已知且活跃：
   - 展示物品摘要；用户选择「补货」后调 `inventory.stock.adjust` 增加数量或新建批次。
4. 未知：
   - 打开新建表单并预填条码；用户填写名称、类型、单位、位置、保质期。
   - 可选：点按「从外部商品库补全」调 `inventory.catalog.lookup`，结果只预填表单，用户确认后才保存。
   - 调 `inventory.items.create { ..., barcodes: [...] }`，物品与条码同事务创建。
5. 归档：
   - 条码命中归档物品时提示「恢复」或「新建另一个物品」，不静默改绑。
   - 恢复后按需重新绑定条码；归档条码不会自动抢占给新物品。
6. 位置可选：用户选 `location_id` 时调 `locations.node.get` 校验存在，不建外键。
7. 可选照片：调 `documents.upload` 上传，再 `documents.link { targetType="inventory.item", role="photo" }`。
8. 批量模式：重复 2–7；每条独立提交，逐条显示成功/失败，已成功项不回滚。

## 4. 失败与补偿

- 非法校验位：拒绝并提示；用户可明确按 `other` 保存，不猜测商品。
- 条码已绑定其他物品：返回冲突，要求先解绑或改绑，不自动覆盖；创建物品时冲突则整笔失败，不留下半建物品。
- 重复扫同一码：同物品幂等，不重复建物品。
- 外部商品库超时/限流/无结果：保留表单，提示可手动填写；不阻塞创建。
- 物品已创建、入库失败：物品保留，提示重试入库；不自动回滚物品。
- 批量部分失败：保留成功项，失败项可重试；不做跨物品事务。
- 相机权限被拒或 Web 不支持：回退手动输入，不反复弹权限。
- 扫码枪输入异常（超长、控制字符）：拒绝并记录计数，不写入映射。
- 离线：本地解析与建物品可用；外部查询不可用，稍后可重试。

## 5. 事件

- `inventory.barcode.changed`
- `inventory.item.changed`
- `inventory.stock.low` / `inventory.stock.expiring`（由数量/批次变化触发）
- 不需要跨模块事务；照片与位置都是可选后续步骤。

## 6. 验收

- 扫已知条码 → 打开物品并可补货；不重复建物品。
- 扫未知条码 → 建物品成功，条码可在物品详情看到。
- UPC-A 与等价 EAN-13 命中同一物品。
- 归档物品被扫到 → 提示恢复，不静默复用。
- 连续扫 10 件，逐条入库；失败项可重试，成功项保持。
- 关闭外部查询或断网时，建物品与入库仍可用。
- 相机帧、条码图片不上传、不落盘；日志不含完整条码。
- Web 手动输入可用；相机不可用不影响其他步骤。

## 7. 开放问题

- 批量扫码是否要「先全部扫描、再统一确认」的两段式；v1 逐条确认。
- 是否允许扫码后直接按 `pack_quantity` 自动加数量；v1 只作为默认值。
- 是否支持称重商品的内嵌价格条码；v1 不解析价格。
- 是否把位置/储物箱二维码纳入同一入口；当前归 `locations`。
- 外部商品库结果是否缓存图片；v1 不缓存、不热链。
