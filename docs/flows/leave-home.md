# 流程：出门前 30 秒，把今天要带的东西凑齐

> 涉及模块：`calendar`、`tasks`、`inventory`、`wardrobe`（天气）、`smart_home`（可选） ｜ 触发：用户点「我要出门」 ｜ 权限：`calendar.read`、`tasks.read`、`tasks.complete`、`inventory.read`、`wardrobe.read`、`smart_home.control`（仅确认后）

## 1. 目标

把「今天要带什么、出门前要做什么」收进一屏，30 秒内看完。清单只做聚合与排序，不替用户判断「伞已经在包里」或「门已经锁了」。所有写操作都回到拥有者：完成任务走 `tasks`，执行场景走 `smart_home`，本流程不建表。

## 2. 参与方与数据所有权

| 数据 | 拥有者 |
|---|---|
| 今日日程、时间、地点 | `calendar` |
| 今日到期任务、垃圾日、带包裹提醒 | `tasks` |
| 待退/待修/借出物品、退货窗口 | `inventory` |
| 天气、降水、体感温度 | `wardrobe`（v1 的天气快照） |
| 离家场景、设备状态 | `smart_home` |
| 门锁状态 | `smart_home`（只读） |

本流程不拥有任何表；出门清单的勾选状态 v1 只存在客户端。

## 3. 步骤

1. 用户点「我要出门」；客户端并行调用：
   - `calendar.events.list { from: 今日 00:00, to: 明日 00:00 }`
   - `tasks.occurrences.list { from: 今日 00:00, to: 今日 24:00, status: "pending" }`
   - `inventory.items.list { status: ["to_return", "in_repair"], returnByBefore: 今日 + 3 天 }`
   - `wardrobe.weather.get`
   - `smart_home.devices.list`（可选，只取门锁与需要离家关闭的设备）
2. 归并成三组卡片：
   - **带**：雨伞、退货包裹、垃圾、任务里写明的物品。
   - **做**：关窗、关灯、带钥匙、给宠物添水等今日任务。
   - **看**：今日日程、天气、门锁最后状态。
3. 天气只做两条建议：有降水且 `rain_ok` 未覆盖 → 「带伞」；体感温度低于当日衣物区间 → 「加外套」。天气 `stale` 或失败时标灰，不给建议。
4. 退货/待修物品按 `return_by` 升序；今天或 3 天内到期才出现，显示「最晚 X 退回」。物品状态不自动改。
5. 今日日程只显示时间、标题、地点；**不推断**「这个日程需要带证件」。需要带什么由用户写在任务或日程备注里。
6. 任务项可勾选，勾选即 `tasks.occurrences.complete`；非任务项（伞、钥匙）只在本地勾选，不写库、不产生「已带」事实。
7. 用户点「执行离家场景」→ 二次确认 → `smart_home.scenes.execute { sceneId, idempotencyKey }`。只允许低风险场景；默认不包含门锁、加热、燃气、总阀。
8. 门锁只显示最后上报状态与时间：`locked` / `unlocked` / `unknown`。本流程没有锁门/开锁命令。
9. 关闭页面即结束；v1 不保存出门历史，不做「昨天忘了带伞」统计。

## 4. 失败与补偿

- **模块未安装**：少一张卡，页面仍可用；顶部列出缺席模块，不假装数据为空。
- **天气过期或失败**：显示 `stale`、最后更新时间和「未知」，不输出「不用带伞」。
- **日历查询失败**：直接显示错误，不回退到旧缓存冒充今天。
- **任务与物品重复**：同一 `subject_type=inventory.item` 的任务与物品合并成一条，任务负责「做」，物品提供「为什么」。
- **场景重复点击或超时**：`idempotencyKey` 去重；超时后查 `smart_home.commands.get`，不重复下发。
- **场景部分失败**：逐设备显示失败原因；不回滚已成功的低风险动作，不重试风暴。
- **用户勾了但没做**：系统不知道，不追问、不写事实、不扣分。
- **跨日与跨时区**：以家庭时区当天 00:00–24:00 为准；跨日日程按开始时间归入当天。
- **隐私**：`guest` 不显示日程、物品、门锁；出门页不进锁屏通知，通知只说「出门清单已更新」。

## 5. 事件

- 消费：`wardrobe.weather.updated`、`tasks.occurrence.completed`、`inventory.item.changed`、`calendar.event.changed`（用于缓存失效）。
- 产生：`smart_home.command.changed`（仅在用户执行场景时）；`tasks.occurrence.completed`（仅在用户勾选任务时）。
- 不新增事件；不跨模块事务，页面每次打开重新聚合。

## 6. 验收

- 雨天出现「带伞」，晴天不出现；天气失败时显示未知，而不是「不用带伞」。
- 今天有到期的退货物品或「带包裹」任务时，出现包裹项，可跳到物品详情。
- 今日日程只展示，不自动生成「带证件」。
- 场景执行必须二次确认；取消后不发送任何命令。
- 页面没有任何开锁/锁门入口；门锁只读，未知状态明确显示。
- 勾选任务会写完成记录；勾选伞/钥匙不写库。
- 任一模块缺失时页面仍可用，并明确标出缺席。
- 日志与通知不含日程标题、物品名称与门锁状态。

## 7. 开放问题

- 是否持久化出门清单的勾选，供当天再次打开时恢复；v1 不持久化。
- 是否用门磁/地理围栏自动弹出清单；v1 只由用户点按，避免误报。
- 是否接入通勤、公交、限行等外部信息；v1 不接。
- 「带伞」是否改为复用 `wardrobe` 的 `rain_ok` 组合，而不是独立天气规则。
- 是否需要「回家清单」（取快递、买菜、充电）。
