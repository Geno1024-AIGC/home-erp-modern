# 流程：记录一次运动并查看统计

> 涉及模块：`fitness`、`tasks`、`health` ｜ 触发：完成一次运动 / 补记昨天的运动 ｜ 权限：`fitness.write`、`fitness.read`、`tasks.write`、`health.write`

## 1. 目标

低摩擦记录一次实际运动，并立即得到可解释的统计与目标进度；锻炼提醒仍由 `tasks` 负责，运动损伤/不适另走 `health`，`fitness` 不复制它们的状态。

## 2. 参与方与数据所有权

| 数据 | 拥有者 |
|---|---|
| 运动类型、运动记录、目标、统计口径 | `fitness` |
| 运动提醒/计划任务 | `tasks` |
| 健康记录、损伤/不适 | `health` |
| 成员资料 | `members` |

## 3. 步骤

1. 可选：用户在 `tasks` 建「每周跑三次」提醒；它是普通任务，不与私有运动目标自动关联，完成状态也不回写 `fitness`。
2. 用户打开原生「运动」快速记录，选择运动类型，填写开始时间、时长，可选距离/步数/热量/心率/RPE/备注；可见性默认 `private`。
3. 调 `fitness.workouts.create`，带 `startedAt`、`localDate`、`durationSec`、可选指标、`visibility` 与 `clientId`。
4. 服务端校验时长/指标范围、`localDate` 与 UTC 日期相差不超过 1 天、同成员时间不重叠；返回 `workoutId`。
5. 历史列表调 `fitness.workouts.list`；本人可编辑/归档，其他成员只能看到 `family` 记录。
6. 统计调 `fitness.stats.summary`（必填本地 `from`/`to`），再按需调 `fitness.stats.timeline` 画日/周/月趋势；缺失桶补 0，不做插值。
7. 目标：`fitness.goals.create` 建每周/每月目标；`fitness.stats.goalProgress` 按本地 `asOfDate` 返回进度。
8. 若出现疼痛/受伤：用户另调 `health.records.create` 记录不适；`fitness` 不自动创建健康记录，也不做诊断。
9. 提醒任务完成由用户在 `tasks` 中手动完成；`fitness` 不自动完成任务，任务也不自动生成运动记录。
10. 需要家庭可见时，用户逐条把 `visibility` 改为 `family`；统计仍只汇总请求者可见的记录。

## 4. 失败与补偿

- 重复提交：`fitness.workouts.create` 带 `clientId`，同一成员同一 `clientId` 幂等，重试不生成重复记录。
- 时间重叠：返回 `409 OVERLAP`；用户修改时间/时长或拆成两条，相邻记录允许。
- 运动类型已归档：拒绝新记录；历史记录仍保留并参与统计，需先恢复类型或换类型。
- 私有记录被他人读取：返回 `FORBIDDEN`；管理员也没有破窗入口。
- 统计区间过大：超过 500 个桶返回 `BUCKET_LIMIT`，提示缩小范围或换更粗的分桶。
- 成员已归档：历史可读，但不能继续写入；需要由管理员恢复成员。
- 健康记录创建失败：不影响运动记录；用户可稍后补记。
- 任务完成失败：不影响运动记录；任务状态仍由 `tasks` 管理。
- 网络中断：原生表单保留草稿；v1 在线优先，不做离线同步。

## 5. 事件

- `fitness.workout.changed`
- `fitness.goal.changed`
- `tasks.template.changed` / `tasks.occurrence.completed`（如创建了提醒）
- `health.record.changed`（如另建了健康记录）
- 不需要跨模块事务；运动、任务、健康最终一致即可。

## 6. 验收

- 只记一条运动，也能在概览看到今日/本周统计与最近记录。
- 补记昨天、修改时长/距离、归档/恢复后统计同步变化。
- 私有记录只有本人可见；家庭可见记录才进入他人统计；`guest` 无权限。
- 连续天数在「今天没运动、昨天有运动」时不清零；最长连续天数按请求区间计算。
- 时间线缺失桶为 0，无插值；超过 500 个桶被拒绝。
- 每周/每月目标进度正确，超过 100% 保留真实数值。
- 提醒任务与运动记录互不自动回写；健康记录与运动记录互不复制。
- 日志、审计与通知不含备注、心率、RPE 与精确运动时间；Web 无运动页且拒绝 `fitness.*` RPC。
- 运动类型归档后历史仍可统计，新记录被拒绝。

## 7. 开放问题

- 是否允许从提醒任务一键打开快速记录；当前只跳转，不自动填运动数据。
- 是否允许目标↔任务关联；当前不做，避免家庭可见任务暴露私有目标。
- 是否允许任务完成时自动创建运动记录；当前不做，避免误记与重复。
- 是否允许运动记录反写任务完成；当前不做，任务状态归 `tasks`。
- 是否需要家庭总量/排行榜；当前不做。
- 是否需要运动记录导出；当前不做。
- 是否需要把运动与健康记录关联（如受伤对应某次运动）；当前不建关联。
