# smart_home · DIY 改装与自制设备接入

> 状态：draft ｜ 适用范围：自建/改装设备接入 ｜ 关联：[../smart_home.md](../smart_home.md)、[spi.md](spi.md)

## 1. 结论

可以接，但**软件不能替硬件安全兜底**。家庭 ERP 只负责发现、绑定、状态、命令、审计与联动，不负责漏电、干烧、过热、漏水、门锁失效等硬件安全。

推荐顺序：

1. **外部非侵入式改造**：智能插座、钳形电流互感器、温度/振动/漏水/门磁传感器、红外节点、本地网关。不拆机、不改主电源。
2. **低电压控制面板接入**：用光耦/隔离开关量按钮或指示灯信号，保留原机保护。仍可能失去保修，需评估绝缘与隔离。
3. **主电源/内部电路改装**：只由持证电工按当地规范完成；ERP 不承诺安全，也不把软件联锁当作唯一保护。

热水壶、洗衣机这类带加热、进水、高速旋转的负载，v1 应优先做**监控与提醒**，控制只做低风险、有人在场、可回退的动作。

## 2. 安全边界

- 不绕过原机的干烧保护、热熔断、温控器、门锁、漏电保护、接地与保险丝。
- 软件定时、继电器、自动化都不是安全联锁；必须保留独立的硬件保护。
- 主电源改装必须断电、验电、锁定挂牌，由持证电工完成；使用认证继电器/电源模块、合适熔断器、阻燃外壳、应力消除与接地。
- 加热类负载必须使用满足额定电流与阻性负载的认证开关器件；不要用灯控/低额定值模块，继电器粘连会导致无法断电。洗衣机等电机负载还要考虑启动浪涌。
- 不把 DIY 高功率设备接入无人值守的定时任务；不在 Web 端提供控制入口。
- 改装可能影响保修、房屋保险与合规；先确认当地法规与保险条款。
- 不确定时停在「只监测、不控制」；这是 v1 的默认安全档位。

## 3. 接入分层

| 层级 | 做法 | 拆机/改主电源 | v1 建议 |
|---|---|---|---|
| L0 外部监测 | 智能插座、钳形 CT、温度/振动/漏水/门磁、红外 | 否 | 默认支持 |
| L1 外部控制 | 认证智能插座/继电器控制整机电源 | 否 | 低风险设备；加热设备需水位/温度联锁，默认只监测 |
| L2 面板信号接入 | 光耦/隔离输入读按钮/指示灯，干接点模拟按键 | 是（低电压侧） | 谨慎，按型号评估 |
| L3 主电源/内部改装 | 自建继电器板、改加热/电机回路 | 是 | 不推荐；不在 ERP 安全承诺内 |

L0 是首选：能回答「是否在加热/洗衣、是否完成、是否漏水」，但不会替用户按下开关。

## 4. 参考架构

```text
DIY 设备/传感器
  → 本地协议（MQTT / ESPHome / Modbus 网关 / BLE 网关）
  → ProtocolDriver（.hmod）
  → AdapterInstance
  → DeviceBinding
  → DeviceProfile + Capability
  → CommandDispatcher（校验 / 风险策略 / 幂等 / 审计）
```

- 设备节点只连本地网络；恒星主动连接本地 broker/网关，不做公网端口映射。
- `ProtocolDriver` 负责发现、配对、快照、命令、事件；不直接写核心表。
- `AdapterInstance.config_ref` 指向加密配置；broker 地址、topic 前缀、证书、每设备凭据都不进业务表。
- `DeviceBinding.nativeId` 用稳定标识（MAC/序列号/节点 ID），重复发现不重复建绑定。
- 驱动必须实现可用性（LWT/心跳）、超时、重连退避、按设备熔断；离线时状态标记为未知，不保留“假装在线”。
- 不使用 `rawCommand`；所有命令走 Capability schema 与策略层。

## 5. 能力与 Profile

### 5.1 建议能力

| Capability | 类型 | 说明 |
|---|---|---|
| `power` | 命令 + 状态 | 普通开关，低风险 |
| `power_meter` | 只读 | 电压、电流、有功功率、累计电量、频率、功率因数 |
| `temperature` | 只读 | 温度与单位；用于水温/机体温度 |
| `water_level` | 只读 | 水位/重量换算；没有传感器时不要假装有 |
| `cycle_state` | 只读 | `idle` / `running` / `spinning` / `done` / `fault` |
| `remaining_time` | 只读 | 预计剩余时间；可由功率曲线推断 |
| `door_state` | 只读 | 开/关/锁定；洗衣机门锁 |
| `leak` | 只读 | 干燥/漏水 |
| `vibration` | 只读 | 振动强度/事件 |
| `fault_code` | 只读 | 设备故障码；只展示，不解释为维修建议 |
| `heater_power` | 命令 + 状态 | 加热负载专用；高风险、仅本地、需重新认证 |
| `appliance_power` | 命令 + 状态 | 整机电源；高风险，不作为普通灯控 |
| `cycle_control` | 命令 | 启动/暂停/停止洗衣程序；高风险、仅本地 |

- `power` 不要直接复用到加热器；用 `heater_power` 区分风险，避免一次策略放宽影响所有开关。
- `heater_power.set` 参数必须包含 `on` 与 `maxOnSec`；`on=true` 时缺少水位/温度联锁就拒绝。
- `cycle_control.start` 必须校验门关闭、无漏水、无故障码与当前 `cycle_state=idle`；运行中若可读门锁状态，要求为锁定。不满足就拒绝，不靠 UI 灰按钮。
- `power_meter`、`temperature`、`leak`、`door_state` 是 `reported`；`cycle_state` 由功率曲线推断时为 `inferred`；命令后的开关状态是 `optimistic`，以电表/传感器回传为准。

### 5.2 参考 Profile

- `appliance.kettle`：`heater_power`、`power_meter`、`temperature`、`water_level`、`leak`。
- `appliance.washer`：`appliance_power`、`power_meter`、`cycle_state`、`remaining_time`、`door_state`、`leak`、`vibration`、`fault_code`。
- `sensor.energy_monitor`：`power_meter`，用于只监测不改装的插座/回路。
- `sensor.leak` / `sensor.door` / `sensor.vibration`：只读传感器，可独立绑定。

这些是 DIY 场景建议的内置 Profile 候选，不代表 v1 已实现；v1 仍只使用模块内置 Profile。

Profile 只组合能力与 UI 提示；具体型号、功率曲线、按钮码、topic 映射放在驱动配置或 Profile 数据中，核心不写厂商分支。

## 6. 热水壶

### 6.1 推荐做法

- 智能插座 + 电量监测：判断是否在加热、是否已断电、估算完成；不拆壶。
- 可选壶盖/壶身温度传感器、重量/水位传感器；没有水位传感器时**不允许远程/自动开加热**。
- 保留原机蒸汽开关、温控器、干烧保护与热熔断；不把 ERP 定时器当唯一断电手段。
- 远程控制只允许「有人在场 + 本地网络 + 重新认证 + 水位正常 + 最长加热时间」，且不走自动化。

### 6.2 联锁与失败

- `water_level` 低于阈值：拒绝 `heater_power.set(on=true)`。
- `temperature` 已接近沸点或异常：拒绝开启。
- 开启后 `power_meter` 在 N 秒内没有电流：判定失败并自动关闭。
- 超过 `maxOnSec` 仍持续加热：自动关闭并告警；同时提示检查硬件保护。
- 断电/驱动离线：继电器回到默认断开；设备状态标记未知，不显示“已关闭”。
- 不根据功率单独宣称“水已烧开”；只有温度/沸腾模型或用户确认才能显示完成。

### 6.3 不要做

- 不 bypass 干烧保护、温控器或热熔断。
- 不用调光/可控硅控制加热管。
- 不在无人值守时定时烧水。
- 不把裸继电器板放在潮湿、可燃或儿童可触及的位置。

## 7. 洗衣机

### 7.1 推荐做法

- 电量监测 + 门磁 + 漏水 + 振动：识别待机/进水/洗涤/脱水/完成/故障，推送完成提醒。
- 只读接入优先；远程启动只在机器支持断电恢复/自动续洗，或使用厂商本地模块时考虑。
- 不通过反复断电控制程序；不在运行中切断电源。
- 漏水传感器只负责告警；自动关阀使用独立认证阀门，不依赖 ERP 命令链。

### 7.2 状态推断

- `idle`：低功率待机。
- `running`：功率进入洗涤/加热区间。
- `spinning`：功率与振动同时升高。
- `done`：功率回落到待机并持续 N 分钟。
- `fault`：故障码、异常功率或漏水/门锁异常。
- 推断结果标记 `inferred`，并显示置信度/最后观测时间；不要用推断状态触发高风险自动化。

### 7.3 远程启动边界

- 启动前校验：门关闭（若可读锁定状态，运行中必须锁定）、无漏水、无故障、`cycle_state=idle`、洗涤剂/衣物由用户确认。
- 只允许原生、本地网络、重新认证；Web 与自动化默认拒绝。
- 没有门锁/漏水传感器时，不开放远程启动。
- 运行中只允许「停止」这一类安全动作；停止也要评估机器是否支持，不保证不损坏衣物或机器。

## 8. 驱动实现

- 驱动 ID 建议用协议命名，例如 `mqtt.local`、`modbus.gateway`、`ble.gateway`；不要用设备型号命名。
- MQTT 映射：`<prefix>/<nativeId>/state`、`/availability`、`/command`、`/event`；JSON schema 校验；QoS 1；保留 availability，不随意保留命令。
- 每设备独立凭据与 ACL；禁止通配符写；broker 只监听本地/IoT VLAN；TLS 可选但推荐。
- 驱动只暴露 Capability；不暴露原始寄存器、GPIO 或 shell。
- 命令超时、重试与幂等：同一 `idempotencyKey` 不重复触发；重试前先读状态。
- 事件去重：漏水、门磁、故障码按设备时间去重；未知事件保留但不崩溃。
- 固件版本、信号质量、最后在线时间作为只读元数据；v1 不做 ERP 触发 OTA。
- 驱动日志脱敏：不打印 token、配对码、完整命令参数中的敏感值。

## 9. 策略与联动

- 风险等级：`power` 低；`appliance_power`、`cycle_control` 高；`heater_power` 严重。
- `heater_power` / `cycle_control`：`localOnly=true`、`requiresReauth=true`；只允许原生、本地网络、手动触发；自动化和 Web 默认拒绝。
- 场景只能包含低风险能力；包含高风险能力的场景必须逐次确认，不能静默执行。
- 高风险命令写审计：谁、何时、设备、能力、动作、结果；不记录原始功率波形。
- 设备离线、驱动停用、策略拒绝、联锁不满足都要给出明确错误，不把“已发送”当“已执行”。
- 功率/温度历史：v1 只保留最后值与事件；后续若增加曲线，必须降采样，原始高频数据只在内存短保留，避免用功率曲线长期推断家庭作息。

## 10. 分阶段落地

1. **P1 只监测**：`power_meter`、`temperature`、`leak`、`vibration`、`door_state`；完成提醒、异常告警；无控制。
2. **P2 低风险控制**：认证智能插座控制整机电源；仅本地、有人在场、带最长运行时间与自动关闭；热水壶仍要求水位联锁。
3. **P3 面板信号**：光耦/干接点读按钮与指示灯；按型号评估隔离、保修与误触风险。
4. **P4 主电源/自制板**：仅持证电工与认证模块；ERP 不承担安全认证；默认不纳入 v1 支持范围。

## 11. 验收

- DIY 设备先出现在发现候选，确认后才成为受管设备；未知设备不能控制。
- 设备绑定稳定 `nativeId`；重复发现不重复建绑定。
- `power_meter` 为 `reported`；命令后开关为 `optimistic`，电表回传后校准；离线显示未知。
- 热水壶没有水位/温度联锁时拒绝远程开启；超过 `maxOnSec` 自动关闭；断电默认断开。
- 洗衣机门未锁、漏水、故障或非 idle 时拒绝启动；运行中不通过断电控制。
- `heater_power`/`cycle_control` 仅原生、本地、重新认证；Web 和自动化被拒绝；审计不含原始波形。
- 驱动超时/崩溃按设备熔断，其他设备不受影响；离线状态不伪装在线。
- 功率/温度历史：v1 只保留最后值与事件；后续若增加曲线，必须降采样；日志不含 token、配对码与敏感命令参数。
- 所有高风险动作保留物理/本地控制；ERP 离线不影响原机安全保护。

## 12. 开放问题

- v1 是否开放用户自定义 Profile/Capability；当前只内置 Profile，DIY 设备优先复用。
- 是否为 Profile 增加 `riskOverrides`/`localOnlyOverrides`，避免为每种负载新增能力。
- 是否允许面板信号接入（L2）；需要按型号评估保修、隔离与误触。
- 是否支持厂商本地模块/协议；需要逐型号适配与安全评审。
- 是否允许远程启动洗衣机；当前仅在有门锁/漏水联锁时考虑。
- 是否允许热水壶远程/定时加热；当前默认不允许，除非水位、温度、有人在场全部满足。
- 功率/温度历史保留多久、是否用于能耗统计；v1 只做短周期聚合。
- 是否接入光伏/储能/电费账单；后续独立能源模块再评估。
- DIY 设备的固件更新是否由 ERP 触发；v1 不做，只报告版本。
- 是否允许自动化使用 `appliance_power`；当前仅手动、本地、逐次确认。
